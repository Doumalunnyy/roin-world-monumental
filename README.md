# ROIN WORLD · MONUMENTAL

Многостраничный сайт международной строительной и инженерной компании. В комплекте исходный код, локальный редактор, материалы на русском, английском, арабском, испанском и венгерском языках, автотесты и инструкции для выпуска. Проект запускается самостоятельно на Node.js.

## GitHub Pages

Публичный адрес проекта — [ROIN WORLD](https://doumalunnyy.github.io/roin-world-monumental/). Публикация настроена из ветки `main`. GitHub Actions устанавливает зависимости, запускает тесты, экспортирует страницы и выкладывает каталог `out/` в окружение GitHub Pages.

Для локальной проверки статического экспорта выполните `npm ci` и `npm run build:pages`. При размещении по другому адресу задайте `PAGES_URL`. Страницы, фото, шрифты и языковые ссылки учитывают путь репозитория. Серверный режим разработки запускается обычной командой `npm run dev`.

На GitHub Pages форма позволяет проверить поля и связаться по опубликованному email. Приём заявок на стороне сервера доступен при размещении Node.js-версии по инструкции ниже. Контент можно обновить в локальной CMS и отправить изменения в GitHub.

## Быстрый запуск

Нужны Node.js **22.18+** и npm. Проверенная среда — Windows, Node.js 26.13, npm 11. Команды выполняются из папки, в которой лежит package.json.

```shell
npm ci
npm run dev
```

Откройте [русскую версию](http://localhost:3000/ru), [английскую](http://localhost:3000/en) или [арабскую](http://localhost:3000/ar). В корне сайта настроен переход на русский. При первом запуске npm использует интернет для установки пакетов. Фотографии, шрифт, карта и интерфейс редактора входят в поставку.

Для локального редактирования запустите во втором терминале `npm run cms`, затем откройте [редактор](http://localhost:3000/admin/index.html). Внесите правку, опубликуйте её и обновите страницу в режиме разработки. На работающем production-сервере новая редакция JSON появляется после сборки и выпуска версии. При отсутствии связи с локальным редактором административная страница объясняет способ подключения.

## Что реализовано

- Главная с панорамой из официального архива, фильмом и интерактивной картой сразу после первого экрана. Далее идут компетенции, проекты, показатели, команда, партнёры, сертификаты, карьера и контакты.
- Разделы компании, истории, руководства и команды с отдельной биографией. Проектные материалы связывают сотрудников, площадки и работу на объекте.
- Каталог направлений и их подробные страницы. В каталоге проектов работают комбинируемые фильтры страны и направления. Три проектные карточки содержат отрасль, роль компании и первоисточник. Карточка «Руппура» показывает галерею и архивное видео. Редактор может добавить видеотаймлапсы, этапы и истории сотрудников по мере получения материалов.
- География, партнёры, сертификаты, карьера, новости и медиа, статьи, контакты с пятью представительствами, информационная страница конфиденциальности. Реестр объединяет семь позиций с официальной карьерной страницы. Кадровая служба подтверждает актуальность при отклике.
- Тридцать две страницы в каждой активной локали. Итого 96 адресов в карте сайта при поставляемых данных. После добавления записей число меняется автоматически.

## Технические решения

Next.js App Router и React генерируют HTML страниц из локализованных JSON. Сервер Node.js обслуживает страницы, оптимизирует изображения и принимает запросы формы. Использован TypeScript в строгом режиме. Клиентский JavaScript отвечает за выбор кадра, фильтры, карту, диалоги и форму. Навигация и основной контент доступны в исходном HTML. Шрифт Manrope поставляется в WOFF2, арабская версия использует системный шрифт.

Графитовый фон и индустриальные фотографии задают композицию главной. Светлые разделы отведены каталогу направлений и материалам о людях. Индексы на карточках связаны с каталогом. Лаймовый акцент выделяет навигацию и выбранные точки. Для движения применены CSS и системная настройка reduced motion. Посторонние аналитические скрипты отсутствуют. Нажатие на кнопку фильма открывает плеер и ссылку на оригинал.

| Путь | Назначение |
| --- | --- |
| `app/[lang]/[[...slug]]` | Локализованные страницы, метаданные, хлебные крошки и выбор шаблона |
| `app/api/contact`, `lib/contact.ts` | Проверка и сохранение обращений |
| `components` | Главная, корпоративные и проектные шаблоны, фильтры, медиа, карта и форма |
| `lib/content.ts`, `lib/features.ts` | Адаптер контента и представление записей в интерфейсе |
| `content` | Материалы, переводы, география, состояние языков и подписи |
| `public/admin`, `scripts/cms-config.mjs` | Локальная сборка Decap CMS, схема и публичные настройки |
| `public/images`, `public/fonts` | Фотографии, документы редактора, карта, шрифт и лицензии |
| `tests` | Проверки обработчика и браузерные сценарии |

## Редактор и языки

Decap CMS подходит для редакции, которая обновляет проекты, вакансии и новости партиями. Браузерный интерфейс сохраняет изменения в репозитории. Git даёт историю и откат, а организация выбирает место размещения данных. Обслуживание отдельной базы для контента не требуется. Затраты возникают у выбранного Git-хостинга, сервера, хранилища и процесса сборки. Локальное сохранение проверено через настоящий сервер редактора. Для удалённого доступа требуются корпоративный репозиторий, OAuth и процесс выпуска. [Руководство редактора](docs/cms.md)

Опубликованы RU, EN, AR, ES и HU. Переключатель сохраняет открытый раздел или карточку. В арабской версии интерфейс читается справа налево. Компания согласует тексты в редакторе, статус переводов указан в `content/locales.json`. Сборка проверяет заполнение обязательных языковых полей.

## Сборка и размещение

1. Распакуйте проект или подготовьте закрытый репозиторий. Установите зависимости через `npm ci`.
2. Скопируйте `.env.example` в `.env.local`, укажите в `SITE_URL` окончательный HTTPS-адрес без завершающего слеша. Это значение используется в canonical, Open Graph, sitemap и проверках происхождения обращений. Для пробного запуска оставьте локальный адрес.
3. Настройте закрытый репозиторий редакции и OAuth, если редакторы будут работать удалённо. В публичные настройки CMS записываются только адреса, название репозитория и ветка.
4. После согласования политики и процесса ответа включите обработчик формы. По умолчанию доступна локальная проверка полей, посетитель видит состояние приёма и официальный email. Включённый обработчик сохраняет обращения в закрытом каталоге и требует постоянного диска. Отдельно настраивается почтовая доставка или CRM, если это необходимо. [Настройка формы](docs/contact.md)
5. Выполните команды ниже. На хосте запустите сервер под выделенной учётной записью, завершайте HTTPS на reverse proxy и закройте локальный сервер редактирования от внешнего доступа. Для переиздания контента собирайте новую версию и переключайте процесс на неё после успешной проверки.
   
```shell
npm run build
npm run start
```

В комплекте есть редирект с корня, страницы 404, sitemap.xml, robots.txt, hreflang, canonical и структурированные данные. Окончательные адреса проверьте после назначения домена. Для отката используйте предыдущее состояние исходников и его сборку. Обращения хранятся отдельно от каталога релиза.

## Проверки

```shell
npm test
npm run build
npm run typecheck
npm run lint
npx playwright install chromium
npm run start
```

При запущенной production-версии выполните `npm run e2e` во втором терминале. Для существующего Chrome или Edge задайте `PLAYWRIGHT_CHROMIUM_EXECUTABLE`. Адрес сервера для тестов задаётся переменной `TEST_BASE_URL`. В тестовом окружении приём реальных заявок выключен.
