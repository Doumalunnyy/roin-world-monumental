# Редактор сайта

Decap CMS хранит контент в JSON в репозитории компании. Один набор файлов питает страницы сайта, переключение языков и административный интерфейс. Редактор работает через браузер, локальный файловый сервер или GitHub. Отдельная база данных и платная лицензия CMS для этой реализации не требуются. При удалённой работе команда оплачивает выбранный Git-хостинг, сборки, хранение медиа и сервис авторизации на их условиях.

## Первый запуск на компьютере

1. Из корня проекта выполните `npm ci`, затем `npm run dev`.
2. Во втором терминале из той же папки выполните `npm run cms`. Команда использует Decap Server 3.11.6. При первом запуске npm скачает пакет. По умолчанию порт 8081 доступен только с этого компьютера.
3. Откройте [редактор](http://localhost:3000/admin/index.html), нажмите «Войти», затем выберите раздел в коллекции «Материалы сайта».
4. Разверните карточку и языковое поле, внесите правки и нажмите «Опубликовать». При локальном запуске результат сохраняется в папку `content` на вашем компьютере. Обновите соответствующую страницу сайта, чтобы проверить все три языка.

Для доступа к локальной версии используйте адрес `localhost` или `127.0.0.1`. Сервер редактора нужен только на время работы редактора. Остановите его сочетанием Ctrl+C. Файловый режим не требует GitHub или OAuth.

## Что редактируется

| Раздел редактора | Файл | Доступные операции |
| --- | --- | --- |
| Главная страница | `content/home.json` | Заголовки, позиционирование, альтернативный текст, обложки, корпоративный фильм, изображение команды, её численность и ссылка на источник |
| Направления | `content/services.json` | Заголовки, индекс, описания и перечень работ, иллюстрации |
| Проекты | `content/projects.json` | Новые карточки, страна, отрасль, подтверждённая роль и источник, связанные направления, галерея, видео и таймлапсы, этапы, истории специалистов |
| Компания и люди | `content/company.json` | Вехи истории, руководство и специалисты, биографии и портреты, партнёры и офисы |
| Новости и медиа | `content/news.json` | Создание, изменение и удаление новостей, дата, перевод текста, обложка, источник и видео |
| Вакансии и сертификаты | `content/records.json` | Вакансии с местом работы и описанием, сканы документов, ссылки на оригиналы |
| Переводы интерфейса | `content/ui.json` | Подписи навигации и других элементов по языкам |
| Тексты внутренних страниц | `content/company-ui.json` | Заголовки, пояснения и тексты о работе компании по языкам |
| Подписи фотографий | `content/captions.json` | Описания и атрибуция фотографий по пути к медиафайлу |

При обновлении численности команды исправьте оба поля в разделе «Главная страница». В первом укажите значение в редакционном формате, например `800+`, во втором — адрес корпоративной публикации, подтверждающей это число. У каждого изображения своя подпись на каждом активном языке. Первичную привязку нового изображения задайте в `content/captions.json` ключом с точным публичным путём к файлу и тремя языковыми полями. Затем повторно запустите `npm run dev` или `npm run build`, чтобы этот путь появился в редакторе.

### Публикация проекта

1. Откройте «Проекты» и добавьте карточку. Задайте короткий идентификатор латиницей. Он используется в адресе страницы и должен быть уникальным.
2. Выберите страну на карте. Заполните названия, описание и роль ROIN WORLD на каждом активном языке, приложите первоисточник. Укажите идентификаторы существующих направлений. Для публикации новой страны дополните карту и список вариантов в `public/admin/schema.mjs`.
3. Загрузите согласованное изображение. Добавьте фотографии в галерею и подписи на каждом языке. Для фильма или таймлапса можно указать URL или выбрать загруженный файл, для видео предусмотрена обложка. Для истории сотрудника укажите существующий идентификатор из «Компания и люди».
4. Проверьте страницу соответствующего проекта, выбор страны, переход на язык AR и ссылки на источники. Для уже доступных страниц сохраняйте прежний идентификатор или настраивайте перенаправление со старого адреса.

Медиафайлы попадают в `public/images` и открываются по адресу `/images/имя-файла`. Лучше заранее уменьшать фотографии под размер размещения и использовать WebP или AVIF. Для больших видео используйте согласованный видеохостинг или объектное хранилище. Если исходный кадр иллюстративный, сохраняйте эту пометку в подписи и в реестре медиа.

## Подключение к репозиторию компании

Продакшен-настройку выполняет администратор корпоративного GitHub и домена. Локальный сервер на хостинг не переносится.

1. Поместите проект в приватный GitHub-репозиторий. Папки `content` и `public` должны лежать в корне репозитория. Назначьте редакторам нужные права записи.
2. Подключите совместимый с Decap GitHub OAuth-посредник на HTTPS. Зарегистрируйте OAuth-приложение, настройте его callback и разрешённый домен редактора по инструкции выбранного сервиса. Client Secret хранится только на стороне посредника. [GitHub backend](https://decapcms.org/docs/github-backend/) и [внешние OAuth-клиенты](https://decapcms.org/docs/external-oauth-clients/).
3. В окружении сборки задайте `CMS_REPOSITORY` в формате владелец/репозиторий, `CMS_BRANCH` с веткой публикации, `CMS_OAUTH_BASE_URL` с HTTPS-адресом посредника и `CMS_AUTH_ENDPOINT` с путём входа на нём. По умолчанию используются ветка `main` и путь `auth`.
4. Выполните `npm run build`. Подготовительный скрипт собирает публичные настройки в `public/admin/settings.json`. В них попадают имя репозитория, ветка и адрес сервиса авторизации. Переменные OAuth-секретов скрипту не передаются.
5. Откройте `/admin` на выбранном домене, войдите через GitHub и проверьте создание черновика. Удалённый редактор использует редакционный процесс Decap с ветками и pull request. Настройте CI на проверку контента и сборку, а хостинг — на развёртывание выбранной ветки после утверждения. На демонстрационном сервере с пустыми настройками интерфейс объясняет, что требуется подключение.

Данные хранятся в выбранном компанией GitHub-репозитории и в сборке сайта. Его владелец определяет доступ, резервное копирование и правила рецензирования. Приём заявок через публичную форму настраивается отдельно по инструкции в README. Медиафайлы больших объёмов увеличивают размер истории Git.

## Языки и поля

Для каждого локализованного поля записывается объект с ключами `ru`, `en` и `ar`. Полный список языков и направление письма задаёт `content/locales.json`. Поля в редакторе создаются по массиву `active`. Подписи интерфейса редактируются по ключам `content/ui.json`. Список ключей обновляется при `npm run dev` и `npm run build`.

Чтобы ввести ES или HU, подготовьте переводы корпоративного содержания и интерфейса, добавьте проверенные значения во все локализованные объекты, активируйте код языка в `locales.json` и укажите фактический статус редакторской проверки. Перезапустите сборку, проверьте маршруты, языковой переключатель, хлебные крошки, формы и метатеги. Редактор автоматически покажет поля нового языка во всех группах.

## Поставка и проверка

В `public/admin/vendor/decap-3.18.0` находится браузерная сборка Decap CMS 3.18.0 с нужными чанками, WASM и лицензиями. Посетитель публичных страниц её не загружает. Пакет получен из официального npm registry. При обновлении сверяйте SHA-512 архива с полем `dist.integrity`, заменяйте основной файл вместе с чанками и проверяйте локальное сохранение и OAuth-вход. [Пакет Decap CMS](https://www.npmjs.com/package/decap-cms/v/3.18.0) и [документация локального сервера](https://decapcms.org/docs/decap-proxy/).

Схема полей находится в `public/admin/schema.mjs`. После добавления нового бизнес-поля обновите JSON, типы и вывод сайта, схему редактора и проверки. Для отката опубликованной правки используйте историю Git и новую сборку.


Для интервью создайте выпуск в «Новости и медиа» с текстом и, при наличии, видео. Его идентификатор можно выбрать для сотрудника, заполнив поле интервью в карточке специалиста. Статья появится в разделе команды и биографии. Если источник подтверждает объект на первом кадре, укажите его идентификатор в поле heroProject. Для общей панорамы оставьте поле пустым. Разделы «Обложки разделов» и «Тексты каталога и карты» управляют внутренними обложками и подписями.
